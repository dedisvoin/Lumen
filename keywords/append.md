# append
---

Добавляет **одно** значение в конец массива **in-place** (без пересоздания).
Работает **только с массивами** — кортежи фиксированной арности, `append` на них
запрещён (`error[129]`).
Ключевое слово-оператор со **строгой** формой `append <lvalue-цель>, <значение>;`:
```lumen
append a, 4;            // a: Array[i64] => {1, 2, 3, 4}
append m[0], 100;       // вложенный массив: m[0].items += {100}
append p.items, "x";    // поле структуры: p: strict { items: Array[str] }
append r, 99;           // r — ref-алиас на массив
append *p, 5;           // p: ptr на массив
```
Запятая и `;` обязательны (`append a 5;` — ошибка парсера).

Почему не `a += {v}`: `+=` с кортежем пересоздаёт массив (квадратично на большом числе
добавлений), `append` — быстрый O(1) push в конец существующей ячейки (до ~200× быстрее на
10k итераций: ~66 мс против ~14 500 мс для `+=`).

Поведение по фазам:
- **интерпретатор (`-r`)**: значение вычисляется и **реально добавляется** в целевую
  ячейку (COW-семантика: если массив косвенный/разделяемый — делается копия перед модификацией);
- **транспиляция (`-build`)**: генерирует `rt::append_dispatch(ctx, target, value)` —
  настоящий `push_back` в `std::vector<Box>`;
- **deep-анализ (lint/LSP)**: `append` **исполняется**, как и `=`/`del` — цель и значение
  проверяются (типы, lvalue, индексы), а мутация применяется, чтобы inlay в `echo a` и
  hover показывали актуальное значение. Инертным `append` остаётся только в мёртвой ветке
  (`if (false) { append ... }`) — там он полностью пропускается (dry-exec).

Требования:
- цель обязана быть **assignable lvalue**: переменная, ref-алиас, разыменованный указатель
  (`*p`), член структуры (`p.items`), элемент по индексу (`a[i]`, `a[i].field[j]`, ...).
  Иначе — `error[130]` (`append 5, 1;` — не lvalue);
- цель обязана иметь массивный тип (`Array[T]`, массив-элемент
  `a[0]` вложенного `Array[Array[T]]`). Иначе — `error[129]`
  (`append a[0], 100;` на `Array[i64]` — `a[0]` это `i64`; `append t, 5;` на
  `Tuple[i64]` — кортеж нельзя расширять);
- недопустимы: const/final-цель, `const_receiver`, а также `private`-член чужой структуры.

Типизация: на **обычных** (не `strict`) целях тип расширяется union-правилом —
`append a, 2.5;` на `let a: Array[i64]` даёт `Array[i64 | f64]` (мягкое расширение).
На **`strict`-контейнере** (переменная `strict let a: Array[i64]`, строгое поле
структуры, `*p`/`Ns::m` на strict-ячейке) элемент обязан быть присваиваем декларированному
типу — иначе `error[83]` (`append a, 10.4;` на `strict Array[i64]` не соберётся и не
мутирует; проверка срабатывает и в lint/LSP — как у `=`/`+=`). Вложенность
(`append a[i], x;`) не энфорсится — как и `a[i] = x;` в самом языке.

```lumen
strict let a: Array[i64] = {1, 2, 3};
append a, 4;
for (let i = 5; i < 8; i = i + 1;) {   // 5 6 7
    append a, i;
}
echo a;                                // {1, 2, 3, 4, 5, 6, 7}
```
