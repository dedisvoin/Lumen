# reserve
---

Предвыделяет **ёмкость** массива или кортежа, не меняя длину. Ключевое слово-оператор
со **строгой** формой `reserve <lvalue-цель>, <ёмкость>;`:
```lumen
strict let a: Array[i64] = {};
reserve a, 1024;        // место под 1024 элемента, длина по-прежнему 0
let i = 0;
while (i < 5) { append a, i; i += 1; }   // 0 1 2 3 4 — ни одного перевыделения
echo a;                // {0, 1, 2, 3, 4}
```
Запятая и `;` обязательны (`reserve a 1024;` — ошибка парсера).

Смысл второго аргумента — ёмкость **всего**, а не «ещё N»:
```lumen
let a = {1, 2, 3};
reserve a, 1024;        // ёмкость 1024 при длине 3
reserve a, 2;           // 2 < длины — no-op, усадки нет
reserve a, 0;           // легальный no-op
```

Зачем: без `reserve` каждый `append` сверх ёмкости вызывает перевыделение буфера с
копированием всех элементов (O(n) на каждое удвоение). `reserve` выделяет нужный объём
один раз. На 200k `append` — ~660-690 мс против ~710-720 мс (≈7%: остальное время
уходит на сам интерпретатор цикла).

Требования:
- цель обязана быть **lvalue**: переменная, ref-алиас, разыменованный указатель (`*p`),
  член структуры (`s.items`), элемент по индексу (`a[i]`). Иначе — `error[138]`
  (`reserve 5, 10;` — не lvalue);
- цель обязана иметь контейнерный тип: `Array[T]` или кортеж `!{...}`. Иначе —
  `error[137]` (`reserve x, 10;` где `x: i64`);
- ёмкость обязана быть **целым** числом (любое выражение i8..i64, константа не нужна).
  Иначе — `error[139]` (`reserve a, 1.5;`); отрицательное значение — `error[141]`
  (`reserve a, -1;`).

Особенности:
- `const`-контейнер **разрешён** (в отличие от `append`): ёмкость не является значением,
  поэтому наблюдаемых данных `reserve` не меняет;
- длина (`sizeof(a)`) не меняется никогда, элементы не трогаются, усадки (`shrink`) нет;
- публичного доступа к ёмкости в языке нет — `reserve` только предвыделяет;
- вложенность не энфорсится, как и у `a[i] = x;`.

Поведение по фазам:
- **интерпретатор (`-r`)**: `reserveInPlace` берёт значение цели и вызывает
  `vector::reserve` прямо в **разделяемом** COW-буфере (`RuntimeArray::data`) — общая
  копия массива не создаётся (обычный `mut()` скопировал бы массив целиком, то есть
  ровно тот O(n), который `reserve` обязан убрать). Значения не меняются, поэтому
  безопасно и в мёртвой ветке (`dry_exec`), и в lint/LSP;
- **транспиляция (`-build`)**: генерирует `rt::reserve_dispatch(ctx, target, count)` —
  `std::vector::reserve` в `std::vector<Box>`;
- **deep-анализ (lint/LSP)**: `reserve` исполняется, как и `append`, поэтому целевые
  ошибки (137/138/139/141) видны в редакторе до запуска.

Нет в языке (осознанно вне v1): `capacity()`, `resize`, `shrink_to_fit`.
